# Лабораторная работа 2 - Сравнение подходов к обработке данных

## Обзор
Данная документация описывает реализацию Лабораторной Работы 2, которая фокусируется на сравнении различных подходов к обработке данных. В работе реализованы и проанализированы три различных подхода к обработке данных: многопоточный, многопроцессный и асинхронный.

## Структура Проекта
```
Lr2/
├── data/          # Директория с исходными данными и результатами тестов
├── parsers/       # Реализации парсеров для обработки данных
├── sum/           # Реализации алгоритмов суммирования
└── utils/         # Вспомогательные утилиты и инструменты
```

## Описание Программ

### 1. Многопоточная Обработка (Threading)
#### Описание
Реализация с использованием модуля `threading` для параллельной обработки данных.

#### Особенности
- Эффективна для I/O-bound задач
- Использование GIL (Global Interpreter Lock)
- Общая память между потоками
- Низкие накладные расходы на создание потоков

### 2. Многопроцессная Обработка (Multiprocessing)
#### Описание
Реализация с использованием модуля `multiprocessing` для параллельной обработки данных.

#### Особенности
- Эффективна для CPU-bound задач
- Обход ограничений GIL
- Изолированная память для каждого процесса
- Более высокие накладные расходы на создание процессов

### 3. Асинхронная Обработка (Asyncio)
#### Описание
Реализация с использованием асинхронного программирования на базе `asyncio`.

#### Особенности
- Эффективна для I/O-bound задач с множеством операций
- Кооперативная многозадачность
- Минимальные накладные расходы на переключение контекста
- Необходимость использования асинхронных библиотек

## Анализ Результатов

### Для CPU-bound задач (суммирование)
- Для малых объемов данных (10^6 - 10^7) все подходы показывают сопоставимую производительность
- При увеличении объема данных (10^8 - 10^10) многопроцессный подход значительно превосходит остальные
- Многопоточный и асинхронный подходы показывают практически идентичные результаты из-за ограничений GIL

### Для парсинга GitHub проектов
- Многопоточный парсер показал наилучшую производительность (25.70 задач/сек)
- Асинхронный парсер занял второе место (23.64 задач/сек)
- Многопроцессный парсер показал наихудшие результаты (19.94 задач/сек)
- Все парсеры успешно обработали по 20 задач из 3 разных GitHub проектов

## Выводы

1. Выбор подхода зависит от характера задачи:
   - Для CPU-bound задач оптимален многопроцессный подход
   - Для I/O-bound задач (парсинг) лучше использовать многопоточный или асинхронный подход

2. Практические рекомендации:
   - Используйте многопроцессный подход для тяжелых вычислений
   - Применяйте многопоточный подход для парсинга и работы с сетью
   - Учитывайте накладные расходы на создание процессов/потоков
   - Для парсинга GitHub проектов предпочтительнее многопоточный подход

3. Ограничения и особенности:
   - GIL ограничивает производительность CPU-bound задач в многопоточном режиме
   - Многопроцессный подход требует больше системных ресурсов
   - Асинхронный код сложнее в отладке и требует специальных библиотек
   - При парсинге GitHub проектов многопроцессный подход менее эффективен из-за накладных расходов
